# Methods

Methods are syntactic sugar for declaring functions on types.

```go
package main

import "fmt"

type User struct {
  Name string
  Age  int
}

func (u User) String() string {
  return fmt.Sprintf("%s is %d", u.Name, u.Age)
}

func main() {
  u := User{
    Name: "Janis",
    Age: 27,
  }

  fmt.Println(u.String()) // Janis is 27
}
```

## Methods Expressions

Methods, as mentioned previously, are just syntactic sugar for functions that have a fixed first argument, the receiver.

```go
package main

import "fmt"

type User struct {
  Name string
  Age  int
}

func (u User) String() string {
  return fmt.Sprintf("%s is %d", u.Name, u.Age)
}

func main() {
  u := User{
    Name: "Janis",
    Age: 27,
  }

  fmt.Println(u.String()) // Janis is 27
}
```

## Methods on Third-Party Types

In a lot of languages, it is possible to define methods on types that you did not define.

```ruby
# Integer is the base class for
# integers in Ruby. Any methods added
# here will be available to all integers
# while the application is running.
class Integer

  # add a greet method to every
  # integer in the application
  def greet
    puts "Hello, I am #{self}."
  end
end

# call the greet method on
# the integer 27
27.greet

# Hello, I am 27.
```

In Go, you are not allowed to define methods on types you did not define.

```go
package main

import "fmt"

func (i int) Greet() {
  fmt.Printf("Hello, I am %d\n", i)
}

func main() {
  i.Greet()
}

// ./main.go:5:7: cannot define new methods on non-local type int
// ./main.go:10:2: undefined: i
```

One solution to this problem is to create a new type based on `int`.

```go
type MyInt int

func (i MyInt) Greet() {
  fmt.Printf("Hello, I am %d\n", i)
}

func main() {
  i := MyInt(27)
  i.Greet()
}

// Hello, I am 27
```

## Functions as Types

Function signatures act as a defacto “type”, but explicit types can also be created for a function signature.

```go
type Greeter func() string

func sayHello(fn Greeter) {
  fmt.Println(fn())
}

func main() {
  sayHello(func() string {
    return "Hello"
  })
}

// Hello
```

## Methods on Functions

By creating a new type for a function, we can treat that type like all types in Go, and it can act as a receiver for methods.

```go
type Calculator func() (int, int)

func (c Calculator) sum() {
  a, b := c()
  fmt.Println("Sum:", a+b)
}

func (c Calculator) sub() {
  a, b := c()
  fmt.Println("Difference:", a-b)
}

func main() {
  var c1 Calculator = func() (int, int) {
    return 5, 3
  }

  var c2 Calculator = func() (int, int) {
    return 10, 7
  }

  c1.sum()
  c1.sub()

  c2.sum()
  c2.sub()
}

// Sum: 8
// Difference: 2
// Sum: 17
// Difference: 3
```

## No Inheritance

When basing a new type on an existing type, any methods that the existing type has are not available on the new type because there is no inheritance in Go.

```go
type User struct {
  Name string
  Age  int
}

func (u User) String() string {
  return fmt.Sprintf("%s is %d", u.Name, u.Age)
}

type MyUser User

func main() {
  u := User{
    Name: "Janis",
    Age: 27,
  }

  fmt.Println(u.String())

  mu := MyUser{
    Name: "Janis",
    Age: 27,
  }

  fmt.Println(mu.String())
}

// ./main.go:29:20: mu.String undefined (type MyUser has no field or method String)
```

Composition via struct embedding

```go
package main

import "fmt"

type Animal struct {
  Name string
}

func (a Animal) Speak() {
  fmt.Println("My name is", a.Name)
}

type Dog struct {
  Animal
  Breed  string
}

func (d Dog) Bark() {
  fmt.Println("Woof!")
}

func main() {
  dog := Dog{
    Animal: Animal{Name: "Buddy"},
    Breed:  "Golden Retriever",
  }

  dog.Speak() // My name is Buddy
  dog.Bark()  // Woof!
}
```
