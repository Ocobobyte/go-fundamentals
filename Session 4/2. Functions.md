# Functions

Functions in Go resemble functions from most other programming languages.

```go
package main

import "fmt"

func main() {
  sayHello()
}

func sayHello() {
  fmt.Println("Hello") // Hello
}
```

## Arguments

Functions can take `N` number of arguments, including other functions. Function arguments are declared as `(name type)`

```go
func main() {
  sayHello("Hello")
}

func sayHello(greeting string) {
  fmt.Println(greeting) // Hello
}
```

When declaring multiple arguments of the same type, the type only needs to be declared at the end of the argument list.

```go
func main() {
  sayHello("Hello", "Kurt")
  sayHello("Hello", "Janis")
}

func sayHello(greeting, name string) {
  fmt.Printf("%s, %s\n", greeting, name)
}

func sayHello2(greeting string, name string) {
  fmt.Printf("%s, %s\n", greeting, name)
}

// Hello, Kurt
// Hello, Janis
```

By always declaring the type for each argument, you make your code more readable, maintainable, and bug resistant.

```go
// Possible bug caused by not declared all argument types
func sayHello3(greeting, i int, name string) {
  fmt.Printf("%s, %s\n", greeting, name)
}
```

## Return Arguments

Functions can return 0 to N numbers of values, though it is considered best practice to not return more than two or three.

```go
func main() {
  fmt.Println(sayHello())
}

func sayHello() string {
  return "Hello"
}

// Hello
```

When returning an error, it is considered best practice to return that value as the last value.

```go
func one() string
func two() (string, error)
func two() (int, string error)
```

## Multiple Return Arguments

Multiple return arguments need to be placed inside of a set of `()` 

```go
func info(s []string) (string, int, int) {
  gs := fmt.Sprintf("%#v", s)
  l  := len(s)
  c  := cap(s)
  return gs, l, c
}

func main() {
  names := []string{"Kurt", "Janis", "Jimi", "Amy"}

  gs, length, capacity := info(names)

  fmt.Println(gs)
  fmt.Println("len: ", length)
  fmt.Println("cap: ", capacity)
}

// []string{"Kurt", "Janis", "Jimi", "Amy"}
// len:  4
// cap:  4
```

When multiple return arguments are used, then all return arguments must be used.

```go
func info(s []string) (string, int, int) {
  gs := fmt.Sprintf("%#v", s)
  l  := len(s)
  c  := cap(s)
  return gs, l, c
}

func main() {
  names := []string{"Kurt", "Janis", "Jimi", "Amy"}

  length := info(names)

  fmt.Println("len: ", length)
}
```

Unwanted return arguments can be ignored by using the `_` placeholder.

```go
func info(s []string) (string, int, int) {
  gs := fmt.Sprintf("%#v", s)
  l  := len(s)
  c  := cap(s)
  return gs, l, c
}

func main() {
  names := []string{"Kurt", "Janis", "Jimi", "Amy"}

  _, length, _ := info(names)

  fmt.Println("len: ", length)
}

// len:  4
```

## Named Returns

You can give the return argument of a Go function a name and use it just like another variable declaration within the function.

```go
func IsValid() (valid bool) {
  valid = true
  return
}
```

It is best practice to not use named returns, unless they are needed for documentation.

```go
func coordinates() (int, int)

func coordinates() (lat int, lng int)
```

## Functions as Variables

Like other types you have seen, such as slices and maps, a function definition can also be assigned to a variable for use later.

```go
func main() {
  f := func() {
    fmt.Println("Hello")
  }
  f() // Hello
}
```

## Functions as Arguments

In Go, functions behave as any other type we have discussed so far. Because functions in Go are types, you can pass them as arguments to another function.

```go
func sayHello(fn func() string) {
  fmt.Println(fn())
}

func main() {
  f := func() string {
    return "Hello"
  }
  sayHello(f)
}

// Hello
```

## Closures

Functions close over their environment when they are defined. This means that a function has access to arguments declared before its declaration.

```go
func sayHello(fn func()) {
  fn()
}

func main() {
  name := "Janis"

  f := func() {
    fmt.Printf("Hello %s", name)
  }
  sayHello(f)
}

// Hello Janis
```

## Anonymous Functions

Anonymous functions are functions that are not assigned to a variable or that do not have a name associated with them.

```go
func sayHello(fn func()) {
  fn()
}

func main() {
  name := "Janis"

  sayHello(func() {
    fmt.Printf("Hello %s", name)
  })
}

// Hello Janis
```

## Functions Accepting Arguments from Functions

Functions can accept the return arguments of one function as its input arguments

```go
func main() {
  takeTwo(returnTwo())
}

func returnTwo() (string, string) {
  return "hello", "world"
}

func takeTwo(a string, b string) {
  fmt.Println(a, b)
}

// hello world
```

## Variadic Arguments

Functions can take variadic arguments, meaning `0` to `N` arguments of the same type. This is done by pre-pending the type of the argument with `…`

```go
func sayHello(names ...string) {
  for _, n := range names {
    fmt.Printf("Hello %s\n", n)
  }
}

func main() {
  sayHello("Kurt", "Janis", "Jimi", "Amy")

  sayHello("Brian")

  sayHello()
}
```

## Variadic Argument Position

Variadic arguments must be the last argument of the function.

```go
func sayHello(names ...string, group string) {
  for _, n := range names {
    fmt.Printf("Hello %s\n", n)
  }
}

// ./main.go:13:21: can only use ... with final parameter in list
```

Slices cannot be passed directly to functions using variadic arguments.

```go
func sayHello(names ...string) {
  for _, n := range names {
    fmt.Printf("Hello %s\n", n)
  }
}

func main() {
  users := []string{"Kurt", "Janis", "Jimi", "Amy"}
  sayHello(users)
}
// ./main.go:13:14: cannot use users (variable of type []string) as string value in argument to sayHello
```

Slices can be expanded using a trailing variadic operator, `…`, to send them as individual argument to a function.

```go
func sayHello(names ...string) {
  for _, n := range names {
    fmt.Printf("Hello %s\n", n)
  }
}

func main() {
  users := []string{"Kurt", "Janis", "Jimi", "Amy"}
  sayHello(users...)
```

## When to Use a Variadic Argument

While using a variadic argument is not the common use case, it certainly can make your code look nicer and be easier to read and use.

```go
type User map[string]string

func LookupUsers(ids []int) []User {
  var users []User

  for _, id := range ids {
     fmt.Printf("looking up id: %d\n", id)
  }
  return users
}

func main() {
  id1 := 1
  id2 := 2
  id3 := 3
  ids := []int{id1, id2, id3}

  LookupUsers([]int{id1})
  LookupUsers([]int{id1, id2})
  LookupUsers(ids)
}
```

With a variadic function signature, the LookupUsers functions can now be called with a single id or a list of ids

```go
type User map[string]string

func LookupUsers(ids ...int) []User {
  var users []User

  for _, id := range ids {
    fmt.Printf("looking up id: %d\n", id)
  }
  return users
}

func main() {
  id1 := 1
  id2 := 2
  id3 := 3
  ids := []int{id1, id2, id3}

  LookupUsers(id1)
  LookupUsers(id1, id2)
  LookupUsers(ids...)
}
```

## Deferring Function Calls

The `defer` keyword in Go allows you to defer the execution of a function call until the return of the parent function

```go
func main() {
  defer fmt.Println("goodbye")

  fmt.Println("hello")
}

// hello
// goodbye
```

## Defer Call Order

The order of execution for deferred function calls is LIFO (Last In, First Out).

```go
func main() {
  defer fmt.Println("one")
  defer fmt.Println("two")
  defer fmt.Println("three")
}

// three
// two
// one
```

## Deferred Calls and Panic

If one or many deferred function calls panics, the panic is caught. The rest of the deferred calls are still executed and then the panic is reraised.

```go
func main() {
  defer fmt.Println("one")
  defer panic("two")
  defer fmt.Println("three")
}

// three
// one
// panic: two

// goroutine 1 [running]:
// main.main.func2()
//        ./main.go:7 +0x25
// main.main()
//        ./main.go:9 +0xf4
// exit status 2
```

## Defers and Exit/Fatal

Deferred calls will not fire if the code explicitly calls `os.Exit` or `log.Fatal`

```go
func main() {
  defer fmt.Println("one")
  os.Exit(1)
  defer fmt.Println("three")
}

// exit status 1
```

```go
func main() {
  defer fmt.Println("one")
  log.Fatal("boom")
  defer fmt.Println("three")
}

// 2025/03/31 23:00:05 boom
// exit status 1
```

## Init

During initialization of a `.go` file, the compiler executes any `init` functions it finds in the file before the `main` function.

```go
package main

import (
  "fmt"
)

func init() {
  fmt.Println("init")
}

func main() {
  fmt.Println("main")
}

// init
// main
```

## Multiple Init Statements

Unlike all other functions that can only be declared once, the `init()` function can be declared multiple times throughout a package for file. However, multiple `init()` can make it difficult to know which one has priority over the others.

```go
func init() {
  fmt.Println("First init")
}

func init() {
  fmt.Println("Second init")
}

func init() {
  fmt.Println("Third init")
}

func init() {
  fmt.Println("Fourth init")
}

func main() {}

// First init
// Second init
// Third init
// Fourth init
```
